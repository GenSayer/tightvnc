
  TightVNC version 1.3.10
  BUILDING vncviewer and WinVNC

======================================================================

  Command-line build (NMAKE): x64, ARM64, ARM64EC, AXP64 and IA64
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

From the vnc_winsrc_64 directory, with the compiler environment for the
target CPU set up (PATH, INCLUDE, LIB):

    build.cmd X64             release build for x64
    build.cmd ARM64           release build for ARM64 (Visual Studio 2019 or
                              2022, ARM64 or cross tools)
    build.cmd ARM64EC         release build for ARM64EC (same tools; cl gets
                              /arm64EC and the linker /machine:ARM64EC)
    build.cmd AXP64           release build for 64-bit Alpha (Alpha64 Win64
                              compiler)
    build.cmd IA64            release build for Itanium (Platform SDK
                              Itanium compiler)
    build.cmd X64 debug       unoptimised build with debug info
    build.cmd X64 htmlhelp    link htmlhelp.lib (see below)
    build.cmd X64 dllcrt      VNCHooks.dll with the DLL CRT (see below)

"debug", "htmlhelp" and "dllcrt" may be given in any order after the CPU.  With no
CPU argument PROCESSOR_ARCHITECTURE picks one; it cannot pick ARM64EC, so
ask for that by name.  Each directory gets its output in Rel_<CPU> (or
Dbg_<CPU>), so builds for different CPUs can live side by side.  The
results are:

    vncviewer\Rel_<CPU>\vncviewer.exe
    winvnc\Rel_<CPU>\WinVNC.exe
    winvnc\Rel_<CPU>\VNCHooks.dll       (copied there by build.cmd)

The 32-bit CPUs i386, ALPHA and ARM are also accepted by build.cmd, with the
same settings as in the vnc_winsrc tree.  They are there for testing only and
are not supported in this tree.

Each directory can also be built on its own with
"nmake /f nt.mak CPU=<CPU> [DEBUG=1] [HTMLHELP=1] [DLLCRT=1]" (build omnithread, zlib,
libjpeg and VNCHooks first).  Shared settings are in nt.inc.  The compiler
switches, defines and libraries are the same as in the Developer Studio
makefiles (WinVNC.mak, vncviewer.mak, WinVNC-axp64.mak, vncviewer-axp64.mak,
WinVNC-ia64.mak, vncviewer-ia64.mak), which still work as before.

VNCHooks.dll is linked with the static CRT by default, so that no CRT DLL
(msvcr80.dll, vcruntime140.dll, ...) has to be installed on the target.
"dllcrt" (DLLCRT=1) builds it with the DLL CRT (/MD) as the original makefiles
do; the compiler's CRT DLL must then be present where WinVNC runs.  The
executables and libraries always use the static CRT.

htmlhelp.lib is not linked by default: the calls into it are commented out in
the sources, because HtmlHelp crashed the programs on IA64 before Windows
Server 2003 SP1.  "htmlhelp" (HTMLHELP=1) links it for the CPU being built;
put a matching HtmlHelp.lib for that CPU in vncviewer\ and winvnc\ (or on
LIB) first, since the one in the tree is for x64 only.  A warning is printed
for IA64 and AXP64 (AXP64 is an Alpha-only Windows build that may be
unstable).

  Building from the source distribution
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The source distribution is ready to compile (all required libraries
are included).

Currently, two build environments are supported: MS Visual C++ 6.0 and
MS Visual C++ 2008. The Workspace files for both these environments
are included in the distribution. Use WinVNC.dsw and vncviewer.dsw
workspace files for Visual C++ 6.0; WinVNC.sln and vncviewer.sln
solution files for Visual C++ 2008. Also, solution and project files
for Visual C++ 2005 are available (files with "-vc8" in their name),
but they may be out of date.

Building with Borland C++ 5.5 compiler is not supported any more,
sorry.

  Building from the CVS
  ~~~~~~~~~~~~~~~~~~~~~

The sources in the CVS do not include third-party libraries required
for successful compilation. These are zlib and JPEG libraries freely
available in the source form from the following locations:

  ftp://ftp.uu.net/graphics/jpeg/jpegsrc.v6b.tar.gz
  http://prdownloads.sourceforge.net/libpng/zlib-1.1.4.tar.gz

Please download these libraries prior to compilation. Note that these
archives are in tar+gzip format not very popular in Windows
environments. To unpack the files, either install appropriate
extractors available for Windows platforms, or unpack them on
Unix-like machines.

After you have downloaded and unpacked the libraries, place their
source files to the locations listed below, NOT overriding existing
files:

  zlib library:
    vnc_winsrc/vncviewer/zlib/
    vnc_winsrc/winvnc/zlib/

  JPEG library:
    vnc_winsrc/vncviewer/libjpeg/
    vnc_winsrc/winvnc/libjpeg/

Also, TightVNC compilation requires Microsoft Html Help SDK which can
be freely downloaded from this page:

  http://msdn.microsoft.com/library/en-us/htmlhelp/html/hwMicrosoftHTMLHelpDownloads.asp

Only two files from the Html Help SDK are required for compilation,
HtmlHelp.h and HtmlHelp.lib. Copy both files to the following folders:

    vnc_winsrc/vncviewer/
    vnc_winsrc/winvnc/

After zlib, JPEG and HtmlHelp files are in place, the source is ready
to compile with either MS Visual C++ 6.0 or MS Visual C++ 2008.
